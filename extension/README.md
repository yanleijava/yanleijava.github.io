# BrowserTools

Chrome 扩展（Manifest V3）工具箱。当前包含两件工具，共用同一套大模型 API 设置：

1. **X AI 回复**：在 X 的单条帖子详情页生成一条短回复，插入回复框。
2. **AI 总结当前网页**：读取当前标签页正文，在弹窗里给出几条要点。

扩展**不会自动发送**帖子或回复，也不会替你提交任何表单。发送必须由你在 X 上手动点击。

## 安装

1. 打开 Chrome，进入 `chrome://extensions`。
2. 打开右上角「开发者模式」。
3. 点击「加载已解压的扩展程序」。
4. 选择本仓库里的 **`extension/`** 目录（这一层要能直接看到 `manifest.json`）。

安装或更新代码后，如果 X 的页面已经开着，请刷新该标签页。

## 填写 API

点击扩展弹窗右上角的「设置」，或在扩展管理页打开选项。

需要填写三项，都保存在本机的 `chrome.storage.local` 里：

| 字段 | 说明 |
| --- | --- |
| API Base URL | 兼容 OpenAI 的地址，通常以 `/v1` 结尾，例如 `https://api.openai.com/v1`。扩展会请求 `{Base URL}/chat/completions`。如果 Base URL 已经以 `/chat/completions` 结尾，则原样使用。 |
| API Key | 只保存在当前浏览器配置里。不要写进仓库。 |
| 模型名 | 由你的接口提供，例如 `gpt-4o-mini`。 |

点「保存」时，浏览器会询问是否允许扩展访问**这个 API 的源站**。点「测试连接」会先保存当前表单，再发一条很短的请求。若刚刚授予权限后第一次测试失败，再点一次即可。

密钥不会出现在扩展日志里。请不要把真实密钥提交到 git。

## X AI 回复

1. 打开 `x.com` 或 `twitter.com` 上**单条帖子详情**（地址里包含 `/status/数字`），并确保回复框可见。若回复框还没收起，扩展会尝试点开回复入口，但不会点发送。
2. 点击工具栏里的 BrowserTools 图标。
3. 在「X AI 回复」里点「生成回复」。
4. 生成的文字会插入回复框。你自己改完后，再手动点 X 的发送。

帖子详情页左下角还有一个不打扰的「生成回复」按钮，作用和弹窗相同。主路径仍然是点击插件图标。

语言：中文帖用中文，英文帖用英文。中英混合看哪边是主体（汉字数量对英文词数量）。日语、韩语、俄语、阿拉伯语能判断就用该语言。判断不了则用英文。

这些情况会给出中文提示：不在帖子详情、找不到回复框、读不到正文、还没配置 API、API 报错。

## AI 总结当前网页

1. 打开一个普通的 `http` 或 `https` 网页。
2. 点击插件图标，在「AI 总结当前网页」里点「总结此页」。
3. 要点显示在弹窗里，可以点「复制」。

总结语言跟随页面主体，规则与回复相同，但判断不了时用中文。正文过长会先截断再送给模型。弹窗里会有「正在读取页面并生成总结…」的加载状态。

`chrome://`、扩展页、空白页无法读取。页面去掉导航、页脚、脚本之后如果几乎没有正文，也会提示抽取失败。这个工具只展示结果，不改页面。

## 不会自动发送

- 不会点击 X 的发送按钮。
- 不会调用发帖接口。
- 总结结果只留在弹窗里，不会写回网页。

## 权限

- `storage`：在本机保存 API 设置。
- `activeTab` 与 `scripting`：只有在你点击扩展图标之后，才读取**当前标签页**的正文。总结功能因此不需要 `<all_urls>`。
- 主机权限 `x.com` / `twitter.com`（含移动版主机名）：在帖子页读取正文，并把回复写入输入框。
- 可选主机权限 `http://*/*` 与 `https://*/*`：API 地址是你事后填写的，安装时无法写死域名。保存或测试时只会请求**该 API 源站**，例如 `https://api.openai.com/*`。这两项可选权限不会用来批量读取网页。

## 开发与测试

```bash
cd extension
npm install
npm test
```

语言判断、回复/总结 prompt、正文抽取与截断、API 地址组装都是不依赖 Chrome 的纯函数，测试在 `extension/tests/`。
